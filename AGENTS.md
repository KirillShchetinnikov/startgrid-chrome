# Локальные инструкции команды StartGrid

Эти инструкции и каталог `.agents/` являются служебной документацией команды.
Они не входят в production build или релизный ZIP. Добавлять их изменения в
обычный product commit следует только по явной инструкции пользователя.

## Режим по умолчанию: экономный

- Обычную задачу выполняет один основной агент без обязательного запуска ролей.
- Подагенты запускаются только по прямой просьбе пользователя либо когда работа
  действительно делится на независимые части и это уменьшает общий расход.
- Рутинная работа и подагенты используют `gpt-5.6-luna` с `low` reasoning.
- `gpt-5.6-terra/low` используется только для архитектуры, хранения, Sync,
  permissions, миграций и других доказанно сложных границ.
- `gpt-5.6-sol`, `high`, `xhigh`, `max` и `ultra` требуют отдельного решения
  пользователя.
- Повышать модель или reasoning можно только для конкретного доказанного риска;
  после сложного этапа нужно вернуться к бюджетной настройке.

## Контекст загружается по необходимости

Перед обычной правкой прочитать запрос, затронутые файлы и релевантные тесты.
Дополнительные документы читать только при наличии соответствующего риска:

- нужный раздел `PRODUCT_SPEC.md` — при изменении поведения пользователя;
- нужный раздел `ARCHITECTURE.md` — при изменении границы, хранения, Sync,
  разрешений, worker lifecycle или зависимости;
- `TESTING.md` — перед браузерными или полными проверками;
- роль и журналы — только если роль фактически запускается.

Не требуется перечитывать `PRODUCT_SPEC.md`, `ARCHITECTURE.md`, все роли и всю
историю журналов для небольших локальных изменений.

## Правила работы

- Сохранять продуктовые инварианты и чужие незавершённые изменения.
- Делать минимальный diff; качество допустимо снижать до уровня «понятно,
  работает, покрыт основной сценарий», без необязательного рефакторинга.
- По умолчанию запускать только узкие проверки затронутой логики. Полные lint,
  Jest/Puppeteer и production build обязательны лишь для релиза, широкого
  изменения или явно запрошенной полной проверки.
- Независимые reviewer и QA не обязательны для малорисковых задач. Они нужны для
  риска потери данных, безопасности, разрешений, миграций, релиза или по прямому
  запросу пользователя.
- Журналы и `CURRENT_TASK.md` обновлять только для многоэтапной/мультиагентной
  задачи, важного решения или релиза. Не копировать туда полные логи команд.
- Commit, push, PR, tag, публикация, релиз и изменения внешних систем требуют
  отдельного явного разрешения пользователя.

После сложного этапа остальные действия снова выполняются на `luna/low`.
